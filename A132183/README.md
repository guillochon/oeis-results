# A132183: regular Boolean functions of n variables

A Boolean function f(x_1, ..., x_n) is **regular** (Muroga: 2-monotonic with x_1 ≥ x_2 ≥ ... ≥ x_n) if it is
monotone and its value cannot drop when a 1 is moved to a stronger variable. **A132183(n)** counts them,
constants included. Knuth entered a(0)–a(9) in 2007 (TAOCP 4A, exercise 7.1.1–109); nothing past a(9) was
known. Minus the two constants this is the number of **complete simple games** with n voters, known to
n = 9 (Kurz and Tautenhahn, arXiv:1001.3045, Table 2: 44 minutes for n = 9 by listing all 2.8·10^11 games).

**Result:** two new terms, by counting instead of listing.

    a(10) = 4191080125665004647
    a(11) = 7950574918162482690174494937400

a(10) takes 37 seconds and a(11) takes 37 seconds per modular pass (four passes) on a desktop PC. The same
runs give the number of self-dual regular functions, which reproduces A109456 up to its last known term
A109456(11) = 1706241214185942.

So the number of complete simple games is 4191080125665004645 for 10 voters and
7950574918162482690174494937398 for 11 voters.

and watch the lattice split into the four copies used in Section 3). A plain-English account is in
[layman.md](layman.md).

## What is being counted

Think of n voters ranked by strength, voter n the strongest. A coalition is a subset A of {1, ..., n}. Say
A ≤ B if B can be reached from A by adding voters and by swapping a voter for a stronger one. In symbols:
|A| ≤ |B| and the i-th largest element of A is at most the i-th largest element of B, for every i ≤ |A|.
This partial order on the 2^n subsets is Knuth's **binary majorization lattice** M(n). A regular function
is a rule "these coalitions win" that respects the order: if A wins and A ≤ B, then B wins. The losing
coalitions then form an **order ideal** (a down-closed set) of M(n), so

    a(n) = number of order ideals of M(n).

For n = 3 the order is ∅ < {1} < {2} < {3}, {1,2} < {1,3} < {2,3} < {1,2,3}, where {3} and {1,2} are the
only incomparable pair. That is a chain with one diamond in it, and it has 10 ideals: a(3) = 10.

The numbers grow fast (a(9) ≈ 2.8·10^11, a(10) ≈ 4.2·10^18, a(11) ≈ 8.0·10^30), so the ideals cannot be
listed. They have to be counted.

## 1. M(n) is a twisted product M(k) × M(m)

Write n = m + k. Split a subset of {1, ..., n} as (A, P): A is its part in the m weak elements {1, ..., m}
and P ⊆ {1, ..., k} records which of the k strong elements m+1, ..., m+k it contains. Call P the
**pattern**. Let ∂A be A without its largest element (∂∅ = ∅).

**Lemma 1.** The order of M(n) is generated by the order inside each pattern class (a copy of M(m)) and by
two kinds of relations between classes, one for each covering pair P ⋖ P' of M(k):

* *move*: P' is P with one element moved up one step. Then (A, P) ≤ (B, P') iff A ≤ B.
* *add*: P' = P ∪ {1} (that is, element m+1 is added). Then (A, P) ≤ (B, P') iff ∂A ≤ B.

*Proof.* The covering relations of M(n) are: add element 1, or move one element up one step into a free
place. A step that stays in {1, ..., m} is a cover inside a pattern class. A step inside {m+1, ..., m+k} is a
*move* with A unchanged. The only other step moves m to m+1, which takes (A, P) with m ∈ A, 1 ∉ P to
(A − {m}, P ∪ {1}) = (∂A, P ∪ {1}). If m ∉ A, first raise the largest element of A to m inside the class;
this does not change ∂A. So (A, P) ≤ (B, P ∪ {1}) iff ∂A ≤ B. ∎

`proto.py` (`check_split`) confirms the two "iff" statements by brute force for several (m, k).

**Consequence.** Let L = J(M(m)) be the lattice of ideals of M(m), and for an ideal I let

    σ(I) = {A : ∂A ∈ I}      (an ideal, and σ(I) ⊇ I).

An ideal of M(n) is the same thing as a family (I_P), one ideal of M(m) for each pattern P ⊆ {1, ..., k}, with

    I_P ⊇ I_P'        for each move cover P ⋖ P',
    I_P ⊇ σ(I_P')     for each add cover P ⋖ P'.

So a(n) counts labelings of the Hasse diagram of M(k) by elements of L, with a containment constraint on
every edge. For k = 2 the diagram is a path of 4 patterns. For k = 4 it has 16 patterns and tree-width 2.

## 2. Zeta transforms on L

Every sum over one I_P is a sum over an up-set or a down-set of L, possibly after applying σ:

    (ζ↑ f)(K) = Σ_{I ⊇ K} f(I),        (ζ↓ f)(J) = Σ_{I ⊆ J} f(I).

* Sum over the lower variable of an add cover: Σ_{I ⊇ σ(I')} f(I) = (ζ↑ f)(σ(I')).
* Sum over the upper variable: Σ_{I' : σ(I') ⊆ I} g(I') = (ζ↓ σ_* g)(I), where (σ_* g)(K) = Σ_{σ(I') = K} g(I').

**Lemma 2 (fast zeta transform on a distributive lattice).** Let p_1, ..., p_N be the elements of M(m) in a
linear extension. For t = 1, ..., N in turn, replace f(J) by f(J) + f(J − p_t) for every ideal J in which p_t
is maximal. The result is ζ↓ f. Running t downward with f(K) += f(K + p_t) gives ζ↑ f.

*Proof.* After all steps, f(J) has collected the original f(I) once for every way to go from I up to J by
adding elements in the order of the linear extension, through ideals. For I ⊆ J there is exactly one way:
add the elements of J − I in that order. Each intermediate set is an ideal, because anything below a newly
added element is in I or was added earlier. ∎

The cost is one addition per edge of the Hasse diagram of L:

| m | ideals of M(m) = a(m) | Hasse edges of L |
|---|---|---|
| 6 | 1173 | 3264 |
| 7 | 44315 | 190162 |
| 8 | 16175190 | 110433364 |

## 3. k = 2: a(m+2) from vectors over L

The patterns form the chain ∅ →add {1} →move {2} →add {1,2}. Write I_00, I_01, I_10, I_11 for the four
ideals. The constraints are I_00 ⊇ σ(I_01), I_01 ⊇ I_10, I_10 ⊇ σ(I_11). Let

    u(J) = #{I_00 ⊇ σ(J)} = (ζ↑ 1)(σ(J)),        w(J) = #{I_11 : σ(I_11) ⊆ J} = (ζ↓ σ_* 1)(J).

Then

    a(m+2) = Σ_J u(J) · (ζ↓ w)(J).

With m = 8 this is a(10): build the 16175190 ideals of M(8) and run three zeta transforms.

## 4. k = 4: a(m+4) from tables on pairs

The 16 patterns of M(4), by rank (sum of elements), with their covers:

    ∅ →a 1 →m 2;   2 →m 3, 2 →a 12;   3 →m 4, 3 →a 13, 12 →m 13;   4 →a 14, 13 →m 14, 13 →m 23;
    14 →m 24, 23 →m 24, 23 →a 123;   24 →m 34, 24 →a 124, 123 →m 124;   34 →a 134, 124 →m 134;
    134 →m 234;   234 →a 1234.

Complementing a subset reverses the order of M(n). On patterns it swaps 14 and 23 and maps the seven
patterns below them, {∅, 1, 2, 3, 12, 4, 13}, onto the seven above them. So it is enough to sum out the
lower half. Write
I* = {complement of A : A ∉ I} for the dual ideal. Eliminating ∅, 1, 2, 12, 3, 4 in that order leaves, for
each pair d = I_13 ⊇ e = I_14,

    P(d, e) = #{(I_∅, I_1, I_2, I_3, I_12, I_4) compatible with I_13 = d and I_14 = e}.

For a fixed d this is five steps on vectors over L (with v = ζ↑ u from Section 3):

    n_d(I_2)  = #{I_12 ⊇ d : σ(I_12) ⊆ I_2}                  = ζ↓ σ_* [· ⊇ d]
    T2(I_3)   = Σ_{I_2 ⊇ I_3} v(I_2) n_d(I_2)                = ζ↑ (v · n_d),   kept only for I_3 ⊇ σ(d)
    T3(I_4)   = Σ_{I_3 ⊇ I_4} T2(I_3)                        = ζ↑ T2
    P(d, e)   = Σ_{I_4 ⊇ σ(e)} T3(I_4)                       = (ζ↑ T3)(σ(e)),   for e ⊆ d.

The middle of the diagram is the square 13 > {14, 23} > 24. The upper half, given I_24 = g and I_23 = f, has
P(g*, f*) completions. Summing e over [g, d] and f over [g, d] independently gives

    R(d, g) = Σ_{g ⊆ e ⊆ d} P(d, e) = (ζ↑ P(d, ·))(g),

    a(m+4) = Σ_{d ⊇ g} R(d, g) · R(g*, d*).

The sum runs over comparable pairs of L. For m = 7 there are 602034981 of them.

Self-dual functions are the ideals with I = I*, that is I_23 = (I_14)* and so on. Their number is

    A109456(m+4) = Σ_{d ⊇ e, d ⊇ e*} P(d, e).

## 5. The computation

`rust/src/main.rs` builds L (ideals as 256-bit sets, sorted; Hasse edges grouped by the removed element;
the maps σ and *), then:

* `k2 m`: Section 3 in exact 64/128-bit arithmetic. m = 8 gives a(10) in 37 s (36 s of it building L).
* `k4 m threads prime`: Section 4. Rows P(d, ·) and R(d, ·) are exact in 128 bits. The products are summed
  modulo one 32-bit prime per run: pass 1 stores R mod p for all comparable pairs (2.4 GB for m = 7), pass 2
  recomputes each row and multiplies it against the stored partners. Four primes give 128 bits, and
  a(11) ≤ a(10)^2 < 2^124 (an ideal of M(11) is a pair of ideals of M(10)). `crt.py` combines the residues.
  The result has 103 bits.

| run | output | time |
|---|---|---|
| `k2 8` | a(10) = 4191080125665004647, self-dual(10) = 1214554343 | 37 s |
| `k4 6` × 4 primes | a(10) = 4191080125665004647, self-dual(10) = 1214554343 | < 1 s |
| `k4 7` × 4 primes | a(11) = 7950574918162482690174494937400, self-dual(11) = 1706241214185942 | 4 × 37 s |

Logs are in `results/`.

## 6. Checks

1. **Known terms.** `proto.py` (Python, exact integers, dense matrices) and the Rust program both reproduce
   a(2)–a(9) from the k = 2 formula (m = 0..7) and a(4)–a(9) from the k = 4 formula (m = 0..5). `proto.py`
   also counts the ideals of M(n) directly for n ≤ 6.
2. **a(10) three ways.** k = 2 on M(8) (Rust), k = 4 on M(6) (Rust, four primes), k = 4 on M(6) (Python,
   exact, dense table B(I_14, I_23)). The two splits share no table: one uses 16175190 ideals of M(8), the
   other 1173 ideals of M(6).
3. **Self-dual counts.** Every run also outputs the number of self-dual regular functions from the same
   tables. They equal A109456(n) for all n ≤ 11, including A109456(10) = 1214554343 (Knuth, 2008) and
   A109456(11) = 1706241214185942 (Minfeng Wang, 2012), which were computed by other people with other
   methods (BDDs). For n = 11 this tests the table P at m = 7, the one a(11) is built from.
4. **Second implementation of a(11).** `verify_dense.py` (numpy) recomputes a(11) modulo 2^31 − 1 with the
   dense table B(e, f) = Σ_{d ⊇ e ∨ f} P(d, e) on all 44315^2 pairs and the contraction
   Σ_{e,f} B(e, f) B(f*, e*), which is a different final step from the Rust program's sum over comparable
   pairs. Result: 1687701734, equal to the CRT value
   reduced modulo 2^31 − 1; its self-dual count 1032135032 is A109456(11) modulo 2^31 − 1 (14 minutes).
5. **Size and parity.** The CRT value has 103 bits against a 128-bit modulus. Complementation is an
   involution on ideals whose fixed points are the self-dual ones, so a(n) ≡ A109456(n) (mod 2): both are
   even for n = 11 and odd for n = 10.
6. **Literature.** a(n) − 2 equals Kurz and Tautenhahn's cs(n) for n ≤ 9 (their Table 2).

## What stops a(12)

The cost is governed by |L|^w, where w is the tree-width of the Hasse diagram of M(k) and |L| = a(n − k).
For n = 12: k = 2 needs vectors over a(10) ≈ 4·10^18 ideals; k = 4 needs tables on pairs of the 1.6·10^7
ideals of M(8) (at least a(9) ≈ 2.8·10^11 comparable pairs, each row costing 10^8 additions); k = 5 and 6
have tree-width 4 and 6 (greedy bounds) over 44315 and 1173 ideals. None of these is within reach of one
PC, so a(12) (roughly 10^52 by extrapolating the ratios) needs a further idea. The same holds for A109456(12).
